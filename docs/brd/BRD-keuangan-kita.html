1. Executive Summary & Problem Statement

Keuangan Kita memadukan kecepatan antarmuka Telegram Bot untuk pencatatan transaksi instan (< 3 detik) dengan kecanggihan Web Dashboard Laravel untuk visualisasi analitik tren keuangan harian, mingguan, dan bulanan.

✕

Masalah Pengguna (Pain Points)

  • Friksi Input Tinggi: Aplikasi konvensional butuh 20–30 detik, pengeluaran mikro sering lupa dicatat.
  • Blindspot Saldo: Sulit mengecek sisa uang riil sebelum belanja di kasir toko.
  • Analisis Manual: Sulit mengevaluasi tren tanpa mengolah spreadsheet rumit.
✓

Solusi Keuangan Kita

  • Input Kilat: Cukup kirim /catat 50000 makan via Telegram, tanggal otomatis terekam.
  • Cek Saldo Instan: Perintah /saldo langsung merangkum kas dan dompet digital.
  • Monitoring Terpadu: Grafik tren harian/mingguan/bulanan di web & rekap otomatis via bot.

6. Non-Functional Requirements & Security Guidelines

Keamanan & Integritas Data

  • No Float Rule: Nominal wajib BIGINT rupiah utuh (menghindari rounding error).
  • Concurrency Locking: Mutasi saldo dalam DB::transaction() dengan lockForUpdate().
  • IDOR Scoping: Proteksi akses data user via Laravel Policy dan User relation scoping.

Vercel Serverless Optimization

  • Sub-second Webhook: Webhook segera kirim 200 OK < 1 detik (cegah retry storm).
  • Stateless Sessions: Session obrolan disimpan di Database/Redis, bukan file session lokal.
  • Ephemeral Storage: Cache dan views dialihkan ke /tmp/storage di runtime Vercel.
